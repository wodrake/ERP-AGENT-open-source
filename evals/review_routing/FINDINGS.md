# 2026-09-25 首轮结论：保留 DeepSeek 默认路由

## 实施与版本

- 实际 WSL 工作副本基于 `c317699`，基线标签 `baseline/pre-jev-20260925`，新分支 `codex/jev-review-evaluation`。
- DeepSeek 请求与响应模型名均为 `deepseek-flash`（服务未返回更细版本）；JEV 固定请求并返回 `jev-1.13.0`。
- 原规则和执行后门控代码未变。只增加可选适配器，并使用原 `ReviewPolicy.astart` 评测。
- 数据在调用前冻结：SHA256 `efbac97f3d21d15764e7e88e6d7c5c54dcaf6c9c99bcad623586c0436ad8d5d8`。
- 总计 200 合成样本、50 场景组（每组 4 变体）；80 开发、120 测试。
- 正式评测每个模型 160 次真实 API 调用，其余 40 条走相同规则；连通性测试另各 2 次。
- 29 项本地回归/适配器测试通过，与真实模型指标分开统计。

## 冻结测试集结果

| 指标 | DeepSeek | JEV |
|---|---:|---:|
| 全体 120 条标签一致率 | 105/120，87.50% | 97/120，80.83% |
| 模糊请求 107 条标签一致率 | 100/107，93.46% | 92/107，85.98% |
| 模糊请求应审查召回率 | 53/60，88.33% | 45/60，75.00% |
| 模糊请求误审率 | 0/47，0% | 0/47，0% |
| 模糊请求 API 有效返回率 | 107/107，100% | 107/107，100% |
| 模糊请求调用 P95 | 1133.06 ms | 1245.79 ms |

JEV 模糊请求一致率低 7.48 个百分点；按场景组配对 bootstrap 的 95% 区间约为 [-14.55, -1.90] 个百分点。
这是该合成基准上的差异，不外推为生产环境或中文整体能力结论。一轮延迟观测也不代表长期性能。
全部 200 条中，两家各 160 次正式 API 调用均返回有效结构；没有通过删除接口失败改善指标。

## 错误来自哪里

1. 两家共同的规则误审：测试集中 8 条只是解释“查询、下单、审查”等词义，却被关键词规则提前送审。换模型无法解决，因为这些题根本不调用模型。
2. 两家都有简单计算/事实查询漏审：例如“按每吨3500元，买750千克要多少”。参考规范要求审查，但原路由提示强调“复杂计算”，两者存在边界差异。
3. JEV 首轮额外漏审包括“把订单O123作废吧”“把这批货登记进仓库”“把这些业务结果做成可下载的Excel”等，说明当前接入提示与判断策略尚不足以取代旧路由。
4. 执行后门控可能补救部分漏审，但本次没执行业务工具，不能假定这些漏审已被成功挽回。

## 决策

默认继续使用 DeepSeek。JEV 代码已接入，可通过配置试用和回退，未自动启用。
不能写“接入 JEV 后准确率提升”；可以写“建立可复现路由评测与可切换模型适配，基于风险召回率开展选型”。

后续若继续优化：先由用户/独立标注者复核产品审查边界，尤其简单计算和只读查询；在开发集调整原子问题或阈值，然后构建新的未见测试集检验。
不得基于已经查看的 v1 测试错误调整后，再把同一集合当未见测试集宣传提升。
改善关键词误审应作为独立实验，两种模型使用同一修正版规则，区分规则收益和模型收益。

## 局限

参考标签由 assistant 编写，未独立人工确认。50 组变体不等于 200 个独立真实任务。
没有评估 task_type/checks 的单独正确率，没有评估主 Agent 最终任务成功率或 Grader 质量。
使用真实模型 API，但不执行 ERP 写操作、不连接业务沙箱、不发送真实企业数据；这避免评测产生副作用。
仅保存 API 返回 token 用量，未读取收费账单，因此不承诺节省费用。
API Key 仅在忽略的本地 `.env` 中，因曾在聊天中提供，建议完成后轮换。
