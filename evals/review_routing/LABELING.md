# 审查路由评测规范 v1

这是 assistant 编写的合成开发基准，不是人工独立标注金标准，也不代表线上用户分布。
200 条来自 50 个场景组，每组 4 个表述；80 开发、120 测试，按组隔离。
标签在调用被测模型前冻结，不根据模型输出改参考答案。测试集不用于调参。

## 标签

- skip：独立寒暄、术语解释、简短语言转换、简单创意或表达偏好，无实际业务判断与执行风险。
- review：业务事实查询、计算、采购决策、多约束、写操作、业务文件交付，或承接未完成的业务任务。
- 上下文不够且涉及执行的模糊指令，按保守业务策略标 review。
- 只解释“下单/审查/查询”等词的含义，不是执行业务，标 skip；这用于暴露关键词规则误审。
- 明确判断的是“按产品规范是否应审查”，不是事后看答案碰巧对不对。

当前所有标签待用户/独立标注者复核。结果称为“合成基准标签一致率”，不能称线上准确率。
人工复核如需改标签，发布 v2 并重新评测两种模型，不覆盖 v1。争议题单列，不挑选有利结果。

## 控制变量与范围

只比较前置路由。规则、输入截断、rubric、主 Agent、Grader、执行后信号均不调整。
执行后门控另由回归测试验证；本基准不执行业务工具，不是订单成功率/端到端成功率。
分别报告全部请求、规则未命中请求和规则命中请求，避免简单题掩盖模型差异。
超时/格式失败保守转 review，纳入总体指标，同时独立报告有效返回率。
开发集和测试集不合并作为主结论。变体相关，单条 Wilson 区间只能参考；正式对比采用场景组 bootstrap。

## 成本与版本

每模型最多 200 次 API 调用；规则命中不调用，默认并发 2、超时 8 秒、不重试。
记录 Git 基线、数据 SHA256、配置、模型响应版本、逐条耗时、用量与失败类型。
未获费用单价时只报告 token 用量，不猜金额。模型置信度不是测得的正确率。
JEV 首轮使用原始 choice，无额外置信阈值（0.0），不在测试集调整阈值。
不得将测试替身的通过率记作真实模型准确率，不使用真实企业数据或密钥作为样本。
